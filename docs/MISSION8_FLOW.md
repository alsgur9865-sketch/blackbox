# BLACKBOX Mission 8 - 고도화 기능 설계 및 흐름 정의서

## 1. 선택한 고도화 기능

**유저 기능 - 개인 투자 습관 개선 플랜**

Mission 7의 BLACKBOX는 거래내역과 투자 습관을 분석해
FOMO 매수, 손절 지연, 정보 과의존, 감정적 재진입 같은 행동 패턴을 보여줍니다.

Mission 8에서는 분석에서 끝나지 않고 사용자가 자신이 고칠 행동을 선택하고
진행 상태와 완료 여부를 관리할 수 있도록 확장합니다.

## 2. 기존 MVP의 한계

기존 MVP는 사용자의 문제를 발견하고 설명할 수 있지만,
분석 이후 실제 개선 행동을 지속적으로 관리하는 기능이 없습니다.

기존:
`문제 발견 → 리포트 확인`

Mission 8:
`문제 발견 → 개선 행동 선택 → 저장 → 진행 → 완료`

## 3. MVP 최소 구현 범위

1. 리포트의 행동 패턴을 개선 계획으로 저장
2. 로그인 사용자별 개선 계획 DB 저장
3. 내 개선 계획 페이지에서 진행 중/완료 목록 조회
4. 진행 중 ↔ 완료 상태 변경
5. 개선 계획 삭제
6. Loading / Error / Empty 상태 제공

결제, AI API, SNS 공유, 알림 기능은 이번 범위에서 제외합니다.

## 4. 사용자 흐름

```text
로그인
  ↓
CSV 거래내역 + 투자 습관 6문항
  ↓
기존 Rule-based 패턴 분석
  ↓
투자 복기 리포트
  ↓
가장 고치고 싶은 행동 선택
  ↓
[내 개선 계획으로 저장]
  ↓
Supabase PostgreSQL 저장
  ↓
내 개선 계획 페이지
  ↓
진행 중
  ↓
[완료하기]
  ↓
완료 기록
```

## 5. 사용자 기준 기능 정의

### 언제 사용하는가?
복기 리포트에서 반복되는 행동 문제를 확인한 직후 사용합니다.

### 어떤 입력을 하는가?
별도의 복잡한 텍스트 입력 없이 리포트에 이미 생성된 행동 패턴 중
자신이 먼저 개선하고 싶은 항목을 선택합니다.

### 어떤 결과를 얻는가?
- 선택한 행동 패턴과 NEXT ACTION이 개인 개선 계획으로 저장됩니다.
- 진행 중/완료 상태를 관리할 수 있습니다.
- 언제 시작했고 언제 완료했는지 확인할 수 있습니다.
- 나중에 다시 진행 상태로 되돌릴 수도 있습니다.

## 6. 기존 MVP와의 통합

기존 Mission 7 기능은 그대로 유지합니다.

- JWT 회원가입/로그인
- CSV 거래내역 업로드
- Rule-based 서버 분석
- PostgreSQL 리포트 저장
- 복기 기록 조회/삭제

Mission 8은 리포트 이후에 `Action Plan` 단계를 추가합니다.

## 7. UX 고도화

### Loading
개선 계획을 서버에서 불러오는 동안 진행 상태를 표시합니다.

### Error
저장/상태 변경/삭제 실패 원인을 사용자에게 안내합니다.

### Empty
저장된 개선 계획이 없을 경우 복기 기록에서 행동을 선택하도록 안내합니다.

### Duplicate
동일 리포트의 동일 행동 패턴은 중복 저장하지 않습니다.

## 8. 기술 선택 이유

### 별도 `action_plans` 테이블
리포트는 과거 분석 결과이고 개선 계획은 이후 변화하는 사용자 상태입니다.
두 데이터를 분리하면 리포트 원본을 변경하지 않고 계획만 안전하게 수정할 수 있습니다.

### 서버에서 패턴 내용 결정
클라이언트가 임의의 제목과 행동 문구를 DB에 저장하지 못하도록
`reportId + patternKey`만 입력받고 서버가 본인 리포트에서 실제 패턴을 찾아 저장합니다.

### Supabase RLS
JWT 사용자 ID와 `action_plans.user_id`를 비교해 본인 데이터만 접근하도록 합니다.
연결된 report 역시 본인 소유인지 INSERT/UPDATE 정책에서 검사합니다.

## 9. 데이터 구조

```text
auth.users
  1
  ├──────── N reports
  │             1
  │             └──────── N action_plans
  │
  └──────────── N action_plans
```

## 10. 성공/실패 검증 시나리오

### 성공
1. 로그인
2. CSV 진단 및 리포트 생성
3. 행동 패턴 하나를 개선 계획으로 저장
4. 내 개선 계획 페이지에서 확인
5. 완료 처리
6. 새로고침 후 완료 상태 유지
7. 다시 진행 처리
8. 삭제

### 실패
- 로그아웃 상태 → 보호 페이지 접근 차단
- 다른 사용자의 리포트 → 계획 생성 불가
- 중복 패턴 저장 → 409 안내
- 잘못된 상태값 → 400
- 서버 오류 → 기존 리포트에는 영향 없음
